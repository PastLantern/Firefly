## 一、后训练

### 1. 长程 Agent 的高效 OPD：按证据收集、按证据回放

- **原标题**：Collect for Coverage, Replay with Evidence: Adaptive and Efficient On-Policy Distillation for Long-Horizon Agents
- **发表日期**：2026-11-25
- **链接**：[arXiv:2611.34756](https://arxiv.org/abs/2611.34756)
- **核心创新**：提出 CARE-OPD，针对长程 Agent 的全在线 OPD 成本过高问题：用学生播种的教师补全加置信度门控扩大历史覆盖、过滤不可靠更新，再用事后执行证据挑选关键回合做回放分配；一条轨迹可支持多次更新。
- **值得看**：在 SWE-bench Verified 上成功率达 59.5%，相对异步在线 OPD 训练时间减少 45%、环境动作减少 44%。做长程 Agent 蒸馏的团队可以直接参考这套“收集—回放”配方。

### 2. 难题数学推理：从被拒的轨迹里挖出多样化解法

- **原标题**：Diverse Alternative Reasoning Traces for Hard Math Problems
- **发表日期**：2026-11-25
- **链接**：[arXiv:2611.34928](https://arxiv.org/abs/2611.34928)
- **核心创新**：提出 DART，从被验证器拒绝的推理轨迹出发，按位置加权不确定性定位关键步骤，用参考答案引导加元思考生成刻意不同的替代候选，再补全成完整轨迹；专治难题下独立采样难以拿到可接受轨迹的问题。
- **值得看**：在未解出的 DeepMath-103K 难题上，比蒙特卡洛采样多恢复 37% 的题目，单条可接受轨迹成本低 30%。用 Llama-3.1-8B 后训练后在 MATH-500 与 AIME 六项评估中五项最优。做数学推理数据挖掘值得借鉴。

### 3. SFT 的灾难性遗忘，可能比你以为的轻得多

- **原标题**：Tune for Retention, Not Just Gain: SFT Forgets Far Less than You Think
- **发表日期**：2026-11-25
- **链接**：[arXiv:2611.34579](https://arxiv.org/abs/2611.34579)
- **核心创新**：挑战“SFT 必然灾难性遗忘”的共识：以增益与保留为联合目标选超参（更低学习率与 batch size），普通 SFT 就能在获得相近新任务增益的同时几乎不遗忘旧能力，可与专为抗遗忘设计的在线自蒸馏方法 SDFT 竞争。
- **值得看**：结论很实用——遗忘不一定是 SFT 离线本性的错，更多是超参选择的问题。做持续微调的团队先调超参再上复杂方法，能省不少功夫。

### 4. 推理努力分层训练：OPD 还是 RL？

- **原标题**：Rethinking Reasoning Effort Training in Large Language Models: On-Policy Distillation or Reinforcement Learning?
- **发表日期**：2026-11-24
- **链接**：[arXiv:2611.32131](https://arxiv.org/abs/2611.32131)
- **核心创新**：系统对比 OPD 与 RL 在“控制推理努力”上的分工：带长度惩罚的 RL 能把单策略的思考在 AIME25 上压缩 70% 且不掉精度，但联合训练多努力档时会坍缩；多教师 OPD 能把低、中档思考 token 分别减少 58% 与 43%，高档还比参考策略高 3.1 分；根源是序列级奖励分不清档位行为，而 OPD 在每个访问状态都给出档位目标。进一步证明在高档上加一个 token 级 KL 锚点，就能让单阶段 RL 学会分层。
- **值得看**：直接回答“想让模型按需思考，该用 OPD 还是 RL”这个部署刚需；结论是压缩靠 RL、分层靠 OPD，混合方案值得一试。

## 二、推理

### 5. BRIAR：沿着推理树的分叉点分配算力与信用

- **原标题**：BRIAR: Martingale Belief Smoothing on Bifurcation-Guided Reasoning Trees
- **发表日期**：2026-11-25
- **链接**：[arXiv:2611.34746](https://arxiv.org/abs/2611.34746)
- **核心创新**：从理论出发：可验证奖励下的前缀通过概率沿推理轨迹构成鞅，早期走错会拖垮整条轨迹、可解题上又会冗余验证；BRIAR 沿置信上界的分叉前沿展开话语对齐的推理树，用边界缩放的异方差边方差建模节点价值，以线性时间的两遍 Rauch–Tung–Striebel 树置信平滑求精确全局后验，并只在吸收后施加零和对数长度中心化的后缀优势。
- **值得看**：把 RLVR 的算力分配与信用分配建立在鞅几何上，框架完整且有理论保证。做长链推理 RL 的团队值得细读。

### 6. 给模型一个理论，值多少推理？

- **原标题**：What Is a Theory Worth to an LLM Solver? Measuring, Inducing, and Merging Theories in Context
- **发表日期**：2026-11-25
- **链接**：[arXiv:2611.34751](https://arxiv.org/abs/2611.34751)
- **核心创新**：在长度匹配的协议下量化“理论”的价值：给 Qwen3-14B 正确的理论，模式等待时间问题的 pass@1 从 0.37 升到 0.83，正确解的中位 token 从 10.2k 降到 6.3k，而同等长度的例题没有帮助；进一步用未发表定理做“植入”实验，测模型自己能否归纳出理论——强模型能恢复 60% 的增益，但多份笔记合并后可达 61%，高于最佳单份笔记的 47%。
- **值得看**：结论耐人寻味——理论值的是它省下的推理，模型能找到理论的碎片，却还组装不完整。提示词里“先给理论再解题”与“让模型自己归纳理论”都有据可依。

### 7. 时间戳到底有没有被模型真正用上？

- **原标题**：Put the World Back: Timestamps Matter in Time Series Reasoning
- **发表日期**：2026-11-25
- **链接**：[arXiv:2611.34848](https://arxiv.org/abs/2611.34848)
- **核心创新**：把时间序列推理重构为“世界到序列的投影”，时间戳是连接数值观测与外部事件的显式索引；设计诊断协议区分“时间戳 grounded 的推理”与“相关性捷径”：310 道受控干预问题显示，把时间戳换成相对偏移或删掉，准确率照样高，但打断事件—序列对齐就会系统性失败；模型只在顺序缺失时才用日期回忆世界知识。
- **值得看**：提醒做时间序列评测的人：预对齐、有序输入上的高分，不等于模型真的会用时间戳同步观测与世界。评测设计值得照搬。

### 8. 能直接读懂世界模型，还要 RL 干什么？

- **原标题**：Do We Still Need Reinforcement Learning When We Can Read the World Model?
- **发表日期**：2026-11-25
- **链接**：[arXiv:2611.34656](https://arxiv.org/abs/2611.34656)
- **核心创新**：提出替代范式：让 LLM 编码智能体直接阅读环境源码（可读世界模型），把环境知识翻译成可执行决策规则，再用在线反馈或离线数据迭代精炼，全程不做任务专用的 RL 训练；在多个决策基准上，合成策略达到或超过传统 RL 方法，且所需经验大幅减少，决策规则还可解释。
- **值得看**：对“RL 是不是必需品”提出正面挑战，适用场景是环境源码可读的决策任务。做仿真、游戏与控制策略的团队可以试试这条更便宜的路。

### 9. 编码 Agent 的补丁，到底有多少是多余编辑？

- **原标题**：How Much Do Coding Agents Over-Edit, and Why? An Empirical Study of Unneeded Edits in Repository-Level Agent Patches
- **发表日期**：2026-11-25
- **链接**：[arXiv:2611.34875](https://arxiv.org/abs/2611.34875)
- **核心创新**：提出 Delta Residue Attribution（DRA），回放智能体轨迹、把补丁每个单元追溯到写它的步骤，逐单元回滚并重跑测试判定是否必需；在 7,660 条已解决的 GitHub Copilot CLI 轨迹上发现：Agent 补丁确实更大，但多余的主要是测试（SWE-bench Verified 上占 61%）和文档；代码的必需程度平均不低于开发者（0.887 对 0.864），SWE-bench Verified 上仍有 11% 的代码单元是不必要的，其中 89% 会改变行为。
- **值得看**：给“Agent 过度编辑”的争论提供了第一份大规模实证：问题不在补丁大，而在少量会改行为的多余代码；作者建议基准在通过率之外同时报告代码必需率，Agent 团队值得据此改进剪枝。

### 10. 深度研究 Agent 的评测：覆盖的知识有多广、多深？

- **原标题**：DRBench Pro: A Knowledge-Centric Benchmark for Professional Deep Research Agents
- **发表日期**：2026-11-25
- **链接**：[arXiv:2611.34852](https://arxiv.org/abs/2611.34852)
- **核心创新**：提出以知识覆盖为核心的深度研究评测：用维基百科自动构建局部知识树并采样子图生成研究问题与证据锚定的评分细则，144 个案例、24 个领域、44,102 条细则，分别度量广度（覆盖多少研究方向）与深度（沿知识链挖多深），几何平均为总分；16 个深度研究 Agent 中最优者总覆盖率 57.04%。
- **值得看**：现有评测多看报告质量，这篇把“研究到了什么”结构化了；细则判断与人工标注高度一致。做深度研究产品的团队可以用它定位自己是广度不够还是深度不够。

### 11. 混合任务 RL：一个策略横跨多领域，还能持续扩展

- **原标题**：Maco-RL: Scaling Agent Capabilities with Mixed-Task Reinforcement Learning
- **发表日期**：2026-11-25
- **链接**：[arXiv:2611.34703](https://arxiv.org/abs/2611.34703)
- **核心创新**：提出 Maco-RL，把混合任务 RL（MixRL）真正规模化：配额调度器做跨领域异步 rollout，平衡梯度贡献、缓解离策略效应；Tri-Buffer Sampling 按掌握程度分配算力，兼顾前沿探索与已有能力保持；Qwen3.5-27B 总分从 43.6 提升到 54.2，持续扩展后到 60.1，追平 Qwen3.8-27B 的前沿水平。
- **值得看**：证明“一个统一策略、不用分专家再蒸馏”在 Agent 能力扩展上是可行且省算力的路线。做通用 Agent 后训练的团队值得参考。

### 12. 50M 参数以下的小智能体，从零训练能走多远？

- **原标题**：ZeroHero: Training Small Language Agents from Scratch
- **发表日期**：2026-11-25
- **链接**：[arXiv:2611.34635](https://arxiv.org/abs/2611.34635)
- **核心创新**：提出 ZeroHero，训练 50M 参数以下的小语言智能体：先用大模型专家轨迹做预训练，再用 PPO 在自交互上后训练，并以“推理对齐”在环境奖励之外补充专家对生成语言的监督；在 Crafter、WebShop、Alfworld-Dialogue 三个多步环境上接近专家水平，部分任务上超过演示专家。
- **值得看**：回答了“专用智能体到底需要多大模型”：小模型加对路的训练法也能胜任。做端侧、专用场景 Agent 的团队值得一看。

### 13. 测试时也能微调 Agent：让督导用自然语言“口头”调参

- **原标题**：vSFT: Learning to Verbally Tune Agents at Test Time
- **发表日期**：2026-11-25
- **链接**：[arXiv:2611.34440](https://arxiv.org/abs/2611.34440)
- **核心创新**：提出 vSFT（verbal SFT），把自然语言的稠密反馈与测试时权重更新结合起来：督导从 Agent 的失败轨迹生成文字监督，超网络把监督转成低秩权重更新来调 Agent；用 Qwen3-4B 在 ALFWorld 上比 GRPO 高 8.7%、比 Reflexion 高 13.9%，WebShop 上分别高 4.8% 与 18.2%。
- **值得看**：把“测试时学习”从上下文反思推进到参数内进化，思路新颖。关注 Agent 自适应的团队值得跟踪。

## 四、递归自我改进（RSI）

### 14. 机器人递归自我改进：工具与策略互相进化

- **原标题**：RoboEvo$^2$: Recursive Robot Self-Improvement via Harness-Policy Co-Evolution
- **发表日期**：2026-11-25
- **链接**：[arXiv:2611.34675](https://arxiv.org/abs/2611.34675)
- **核心创新**：提出“工具—策略协同进化”框架：策略失败引导编码 Agent 搜索代码、代码+示例、代码+策略三条互补路线，把验证过的解法沉淀为可复用技能与经验记忆；验证过的轨迹再做监督训练，反事实偏好蒸馏（CPD）教策略偏好同一起点的成功修正；无需新增人类演示，LIBERO-PRO 上独立成功率从 11.0% 提升到 84.1%，混合成功率从 30.4% 提升到 90.5%，Unitree G1-D 上混合成功率 95.0%。
- **值得看**：本期 RSI 板块最亮眼的实证：推理与实践互相喂养的闭环真的能跑通。做具身智能与 VLA 的团队必读。

### 15. 知识库梯度下降：用问答驱动知识库自我结构化

- **原标题**：Knowledge-Base Gradient Descent: Self-Structuring Learning through Question Answering
- **发表日期**：2026-11-25
- **链接**：[arXiv:2611.34841](https://arxiv.org/abs/2611.34841)
- **核心创新**：提出 Self-Structuring Learning：用问题与期望答案指导持久知识库的结构构建；Knowledge-Base Gradient Descent 诊断当前知识库回答与期望答案的差异，每轮提议结构编辑、重建知识库、损失下降则采纳，并把编辑的损失变化表达为选择概率的导数；在大文档束（研究论文合集）上，更新后的知识卡与图模式在留出问题上的平均 Answer F1 均高于初始结构。
- **值得看**：把“梯度下降”的思想搬到知识库结构本身，RAG 系统的知识组织可以从静态人工设计走向数据驱动的自我改进。做企业知识库与研究助手的团队值得一读。

### 16. 长程 Agent RL 全员失败时：把失败轨迹“剪接”成局部训练目标

- **原标题**：When Every Rollout Fails: Splicing Learner-Conditioned Options into Long-Horizon Agent RL
- **发表日期**：2026-11-25
- **链接**：[arXiv:2611.34777](https://arxiv.org/abs/2611.34777)
- **核心创新**：提出 SPLICE，解决长程 Agent 任务中整组 rollout 全失败、组相对方法拿不到奖励梯度的问题：不直接搬完整专家解，而是在当前策略的失败轨迹上选剪接点、生成有界候选选项，用多次当前策略续写估计选项价值，转成回报加权的局部目标来拟合；在 SWE-bench Verified 与 BrowseComp-Plus 上比 GRPO 高 2.8–9.8 个百分点，初始失败任务的毕业率提升 10.8 个百分点。
- **值得看**：全失败组是长程 Agent RL 的常见死局，这篇给出了一种比“喂完整专家轨迹”更便宜、更在线的解法。做 Agent RL 的团队可以直接用。

### 17. 自进化 Agent 的评测：经验到底能不能复用到后续任务？

- **原标题**：EvoLink-Bench: A Benchmark for Evaluating Self-Evolving Agents in Long-Horizon Interdependent Task Streams
- **发表日期**：2026-11-25
- **链接**：[arXiv:2611.34400](https://arxiv.org/abs/2611.34400)
- **核心创新**：提出首个面向“自进化”Agent 的长程评测：任务流跨日常办公、多轮对话与 AutoResearch 场景，带持久工作区与跨任务依赖，分 L1（语言可表达知识的获取与修正）与 L2（执行中发展任务级能力）两层，区分任务内恢复、持久状态更新与后续任务的经验复用；评估 5 个框架、19,635 个评分任务槽发现：没有框架在两层都最优，重试只能恢复有限失败，持久状态更新不一定改善后续表现。
- **值得看**：结论冷静——“会学习”不等于“学到的能复用”，知识层与能力层的进化需要不同的学习机制。做记忆与自进化 Agent 的团队应以此为基线。

## 五、数据

### 18. PersonaFactory：用 74 万合成人格让用户提示更多样

- **原标题**：PersonaFactory: Stylistic User Prompt Augmentation with Synthetic Persona Bank
- **发表日期**：2026-11-25
- **链接**：[arXiv:2611.34785](https://arxiv.org/abs/2611.34785)
- **核心创新**：提出端到端管线，生成结构化用户人格并用其改写现有用户提示，产出 74 万多结构化合成人格与约 124 万条覆盖 85 种语言的人格化合成对话；结构化属性表示在同等风格保真度下比自由文本人格更好地保持意图，人工评估认为对话可信、意图保持与多语言真实性均获好评。
- **值得看**：合成用户数据常被诟病“风格扁平、千人一面”，这篇给出可规模化的人格多样化方案。做对话数据合成与个性化助手训练的团队值得参考。

### 19. ConTra：让检索的上下文跟着文本块走

- **原标题**：ConTra: A Training Framework for Effective Contextual Retrieval via Prefix Generation
- **发表日期**：2026-11-25
- **链接**：[arXiv:2611.34366](https://arxiv.org/abs/2611.34366)
- **核心创新**：提出 ConTra，用强化学习训练轻量前缀生成器：奖励结合冻结嵌入与重排模型的反馈、事实验证与长度控制，为每个文本块生成前缀，兼顾向量检索与文本重排；2B 的 ConTra 在 ConTEB 与 RealContextBench 上超过用 Anthropic 方法的 9B 提示基线与 PPLX-4B 上下文编码器，短文档索引速度快 7.74 倍与 2.15 倍。
- **值得看**：上下文检索的老问题（切块丢上下文）的新解法：小模型生成前缀，大模型只管用。做 RAG 索引与企业文档检索的团队值得一试。

### 20. 代理模型选错数据时：用多保真度 bandit 纠正错配

- **原标题**：When the Proxy Is Wrong: Mismatch-Corrected Bandits for Adaptive Data Sampling
- **发表日期**：2026-11-25
- **链接**：[arXiv:2611.34707](https://arxiv.org/abs/2611.34707)
- **核心创新**：把“小代理模型给大目标模型选数据”的错配建模为多保真度 bandit：每臂是一个数据干预，代理奖励每轮可见，目标奖励只在稀有审计中揭示；用成对观测识别臂级错配、只审计不确定的决策、把审计预算分摊到整个训练过程；理论上证明仅用代理分配可导致线性遗憾，而滑窗策略达到 O(√ΓT log T) 的遗憾界；在 CivilComments-WILDS 上纠错后最差组准确率提升 6.3–10.5 个百分点。
- **值得看**：数据配比与课程学习里代理模型很常用，这篇首次给出“代理不可信时怎么办”的带理论保证的方案。做数据筛选与采样策略的团队值得读。

## 六、预训练与架构

### 21. 循环 Transformer 的新解法：用 KV 当跨层记忆

- **原标题**：Mixture-of-Loops Transformer
- **发表日期**：2026-11-25
- **链接**：[arXiv:2611.34923](https://arxiv.org/abs/2611.34923)
- **核心创新**：提出 MoLT，重新思考循环之间该传递什么：Mixture-of-Loops Attention（MoLA）把 KV 作为记忆跨深度与循环选择性复用；U 形变体 U-MoLT 分离记忆构建与预测读出，可跳过不用的解码遍历且不改变预测；400B token 预训练中 U-MoLT 在 700M/1.5B 稠密与 3B MoE 上均超过 OLMo3，700M 上验证交叉熵 token 效率达 1.7 倍。
- **值得看**：循环架构近期回暖，这篇把“循环间传递什么”讲清楚了，且在 MoE 上也有增益。关注高效架构的团队值得跟踪。

### 22. 循环 MoE 的增益，到底来自参数重访吗？

- **原标题**：LoopTitan: What Does Parameter Revisit Buy a Mixture-of-Experts?
- **发表日期**：2026-11-25
- **链接**：[arXiv:2611.34821](https://arxiv.org/abs/2611.34821)
- **核心创新**：用匹配的非重访对照做分解，结论出人意料：参数重访本身几乎没有带来增益，大部分增益来自网络形状，其余来自残差缩放（在 AdamW 下等效于降低重访层的学习率，在 Muon 下消失）；不重访的更深标准 MoE 在同等参数与算力下能拿到重访增益的 90.2%；据此提出的 LoopTitan-Base 在 Muon 下无需重访与残差缩放就能匹敌最强循环配方，并开源 17 个预训练模型。
- **值得看**：一篇很好的“祛魅”论文：循环 MoE 的红利可能被归因错了。做架构选型的团队读完再决定要不要上循环。

### 23. 分词器优化，理论上就不存在好的近似算法

- **原标题**：Tokenisation is not in APX
- **发表日期**：2026-11-25
- **链接**：[arXiv:2611.34938](https://arxiv.org/abs/2611.34938)
- **核心创新**：证明除非 P=NP，不存在多项式时间算法能找到目标值在最优解常数因子内的分词器，即分词不在 APX 复杂性类中；结论对直接式与自底向上两种分词、在压缩或单字对数似然目标下、二元或更大字母表上均成立，甚至在一元字母表上直接分词也是 APX-hard 的。
- **值得看**：给分词器设计划了一条理论边界：别再找通用最优算法了，启发式与领域特化才是正道。做 tokenizer 与预训练的团队值得收藏。

### 25. 解视觉推理题，写代码比生成视频更靠谱

### 26. 医疗多模态大模型：35B 参数、3B 激活，逼近 GPT-6.2-Sol

### 27. 推测解码也能“蹭”目标模型的稀疏注意力

- **原标题**：DFly2: Turbocharging Long-Context Speculative Decoding by Sharing the Target's Sparsity
- **发表日期**：2026-11-25
- **链接**：[arXiv:2611.34776](https://arxiv.org/abs/2611.34776)
- **核心创新**：提出 DFly2，针对 DeepSeek-V4、Hy4 这类原生稀疏模型：起草器不再自建上下文缓存，而是共享目标模型已有的 KV 缓存与每查询的位置选择（KV 共享 + 索引共享），不跑打分、不存缓存；在 DS-V4.1-Flash、GLM-5.3-Flash、Hy4-flash 上每步接受 token 数超过同配方训练的 DFlash 与 DSpark，长上下文与 Agent 负载上的领先幅度扩大到 10.0%–31.5%，高并发下同等单用户解码速度时吞吐高 62% 与 81%。

### 28. 一份权重、2–8 位任意精度：半比特步进的量化

- **原标题**：Any-Rate: Half-Bit Multi-Precision LLM Quantization with Coded Bit-Planes
- **发表日期**：2026-11-25
- **链接**：[arXiv:2611.34402](https://arxiv.org/abs/2611.34402)
- **核心创新**：提出 Any-Rate，让一份 checkpoint 以半比特步进服务 2–8 位精度：把部分位平面限制为 8 权重块上的扩展汉明码字（每权重 0.5 位），各精度共享每行一个查找表并联合编码；在 2 位与 3 位上达到多精度方法中最优精度，2 位保留 FP16 准确率的 69%，4 位与最优方法差距在 1 分以内；同等精度下 LPDDR 能耗模型估计省电可达 27%。
- **值得看**：端侧部署常要在内存与电量预算之间换档，这篇让“一份权重、多档精度”在 2 位也不崩。做端侧与多精度部署的团队值得收藏。

### 29. 监控器评测可能被“攻击策略的选择”误导

- **原标题**：Attack Policy Selection can Mislead Monitor Evaluators
- **发表日期**：2026-11-25
- **链接**：[arXiv:2611.34934](https://arxiv.org/abs/2611.34934)
- **核心创新**：以一个已下线的 OpenAI 生产监控器为案例研究：测得的漏报率对攻击策略的生成方法与优化程度高度敏感——同一种 RL 方法在不同优化水平下漏报率从 0.5% 到 20.8%，不同方法在各自最优水平下从 6.4% 到 23.0%，且所有攻击都迁移到了未参与开发的 GPT-5.4 目标监控器；攻击轨迹中的代理产物（如监控器看不到的“支线任务”推理）还会影响监控器判断。
- **值得看**：结论直指安全评测的方法论：只用基础攻击方法评测会给人监控器很强的假信心；把评测结果解读为部署表现，需要额外论证代理行为的合理性。做 Agent 安全与监控的团队必读。

### 30. 水印攻防：攻击者会读设计、挑打法，现有水印全军覆没

- **原标题**：Know the Design, Pick the Attack: Sentence-Keyed Watermarks for LLMs
- **发表日期**：2026-11-25
- **链接**：[arXiv:2611.34505](https://arxiv.org/abs/2611.34505)
- **核心创新**：研究一种会“读公开设计再选打法”的攻击者：难学的就改写擦除，耐改写的就学下来伪造；在此攻击者面前，比较的现有水印全部失效；据此提出 KeyedLex，密钥取自上一句的语法（改写影响小），检测器无需精确恢复密钥，在两个模型上均优于所有对比水印，信号损失约一半（最优对照损失三分之二），且不牺牲文本质量。
- **值得看**：水印设计不能只防一种攻击；KeyedLex 的“句子语法作密钥”思路简洁有效。做文本溯源与内容 provenance 的团队值得一读。
