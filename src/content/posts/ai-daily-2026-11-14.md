## 一、后训练

### 1. [只用负样本做强化学习：验证器只能证伪时怎么训](https://arxiv.org/abs/2611.17287)

*Negative-Only Policy Optimization for One-Sided Verifiable Rewards*

`arXiv:2611.17287` · 2026-11-12

| 指标 | 数值 |
| --- | --- |
| 核心设定 | 只抑制可信负样本 |
| 正样本处理 | 当无标签样本 |

**核心贡献**　带可验证奖励的强化学习（RLVR）通常假定验证器能可靠判断正误，但现实中廉价检查往往只能证伪失败、不能证实正确。作者把这种情形形式化为“单侧可验证”：已验证的负样本是可信反例，正样本只是“未被证伪”，可能含大量假阳性。据此提出 NOPO，把正样本当无标签样本、只用可信负样本做抑制更新，结合参考相对的负抑制损失与按未证伪比例缩放更新的组级适配器。

**为什么值得读**　验证器不完备是 RLVR 落地的常态——单元测试、约束检查、LLM 自评大多只能证伪。作者自报 NOPO 在代码、逻辑与数学基准上提升 pass@k，且在推理时扩展与跨基准迁移中保持增益。

### 2. [奖励之外的能力漂移：多语言后训练的隐性代价](https://arxiv.org/abs/2611.15717)

*Outside the Purview of the Reward: Capability Drift in Multilingual Post-Training*

`arXiv:2611.15717` · 2026-11-11

| 指标 | 数值 |
| --- | --- |
| MATH | **+36.07** 分 |
| XQuAD-Indic | **−19.32** F1 |

**核心贡献**　后训练能改善被奖励的行为，同时削弱用户仍需要的能力。作者研究同一监督检查点的两个 GRPO 分支：发布分支 MATH 提升 36.07 分，但 XQuAD-Indic 下降 19.32 F1（英文 XQuAD 反而提升）；另一分支加入 Indic 指令遵循与语言感知 shaping 后，恢复了退化的 Indic 分数并保留 MATH，但脚本合规性仍未恢复。对 MATH 增益的分解显示，大部分增益来自“输出带框答案”的比例上升，而非框内答案准确率的提升。

**为什么值得读**　读基准分数时必须连同被奖励的回答形式一起解读。做多语言后训练、做 RL 的人，这是本期最该先看的警示。

## 二、数据

### 3. [固定预算下，人标数据还是合成数据更划算](https://arxiv.org/abs/2611.16895)

*Human or Synthetic? What a Fixed Budget Buys for Post-Training*

`arXiv:2611.16895` · 2026-11-12

| 指标 | 数值 |
| --- | --- |
| 合成数据 | **$200—400** 取得高胜率 |
| 人标追上 | 约 **100×** 预算（仅有用性任务） |

**核心贡献**　以往比较人标与合成偏好数据时固定样本量，忽略了单样本成本的巨大差异。本文改在“美元对齐的固定标注预算”下比较：低到中等预算下合成数据性价比远高于人标，200—400 美元即可取得高胜率；有用性任务上人标要到约两个数量级更大的预算才追上，摘要任务上在所有测试预算下都追不上。且人标数据源本身的可靠性差异很大，一个常用的人标偏好源明显弱于另一个。

**为什么值得读**　做偏好数据采购与预算分配时直接可用的决策依据：先算清每美元能买多少有效信号，再决定人标还是合成。

## 三、预训练与架构

### 4. [ArchSpace：让架构研究可记录、可评审、可引用](https://arxiv.org/abs/2611.17332)

*ArchSpace: Recording, Reviewing, and Referencing LLM Architecture Research*

`arXiv:2611.17332` · 2026-11-12

| 指标 | 数值 |
| --- | --- |
| 初始基线 | Qwen3.5 · OLMo3 |
| 附带资产 | 拟合缩放定律 + 训练配方 |

**核心贡献**　模型架构决定大模型的扩展、训练效率与推理成本，但业界报告很少记录哪些架构想法成功、哪些被放弃及原因，学术界又常受限于小规模单点比较，难以判断改进能否泛化到大尺度。ArchSpace 是记录、评审与引用架构研究的公开平台，用缩放定律从小实验预测大尺度损失，并提供 Qwen3.5 与 OLMo3 基线、拟合好的缩放定律与可复用训练配方作为初始参考。

**为什么值得读**　做架构探索、想在小算力下预判大模型效果时可参考；平台沉淀的架构经验——尤其是哪些想法被证伪——值得长期关注。

## 四、推理

### 5. [扩散语言模型何时该重写：一个轻量验证器说了算](https://arxiv.org/abs/2611.17320)

*Learning When Diffusion Language Models Should Regenerate*

`arXiv:2611.17320` · 2026-11-12

| 指标 | 数值 |
| --- | --- |
| 准确率 | 35.3% → **43.4%** |
| 解码成本 | 贪心解码的 **1.9—3.5×** |

**核心贡献**　扩散语言模型可通过重掩码 revisiting 生成文本，但何时、改哪里一直不清楚。作者在数独上的诊断发现两个缺口：隐藏状态含有 token 置信度暴露不出的错误信息；且孤立地重掩码单个错误常因上下文不变而重蹈覆辙。据此提出 DiVR 验证器：预测部分生成序列能否到达正确答案，决定何时重生成整块、保留哪个候选，生成器本身不动。

**为什么值得读**　用扩散语言模型（如 LLaDA、Dream）做推理时可直接参考：不动生成器，只加一个轻量验证器来决定“何时重写”。

### 6. [决策模型当演员、当评委还是当老师：差演员也能当好老师](https://arxiv.org/abs/2611.17167)

*Actor, Judge, or Teacher? Understanding Decision Models in Long-Horizon Agents*

`arXiv:2611.17167` · 2026-11-12

| 指标 | 数值 |
| --- | --- |
| ALFWorld | 72.8% → **82.9%** |
| WebShop | 56.8% → **71.4%** |

**核心贡献**　决策模型一次输出带概率的类型化选项，可当演员选动作、当评委评估已做动作、或给每个动作打分来教策略，以往只按“当演员好不好”评价。作者发现：当演员时 6 个模型都会被更容易的子目标带偏、错过必须先做的子目标；当评委时，看到完整轨迹的同一批模型能给通向子目标的步骤加分，且问“这个动作有没有帮助”比问“任务会不会成功”更能区分动作好坏；当老师时效果最好（见上图）。

**为什么值得读**　决策模型不一定要自己会做事——用它当老师教小策略模型可能更划算。做长程 Agent 训练时，“事后评判揭示行动后果”这一机制值得借鉴。

## 五、Agent 与工具

### 7. [编码智能体的记忆该留什么：按“前瞻价值”算账](https://arxiv.org/abs/2611.17316)

*CoReMem: Cost-Internalizing Memory for Successive Coding Tasks with Prospective Valuation*

`arXiv:2611.17316` · 2026-11-12

| 指标 | 数值 |
| --- | --- |
| 解决率 | 21.0% → **25.7%** |
| 步数 | **−17%** |
| 总 token | **−11%** |

**核心贡献**　编码智能体在演进仓库上连续做任务，要在不知道下一任务时决定写什么记忆。CoReMem 用“前瞻价值”度量记忆：比较下一任务有/无某段轨迹片段时的运行结果，围绕仓库位置与可执行检查等锚点构建紧凑记忆；执行器再用带/不带记忆的同策略 rollout，在组内估计记忆的在策略价值，奖励优先解决任务、成功时惩罚步数。

**为什么值得读**　给编码 Agent 接长期记忆时可直接参考：记忆该留什么，不靠直觉，靠它对下一个任务的实际价值算账。

## 六、多模态

### 8. [多模态视觉编码拆开看：预训练先验没那么重要，专用视觉容量才关键](https://arxiv.org/abs/2611.17334)

*Unbundling Multimodal Vision Encoding*

`arXiv:2611.17334` · 2026-11-12

| 指标 | 数值 |
| --- | --- |
| 视觉先验 | 并非必需 |
| 关键因素 | 专用视觉容量 |

**核心贡献**　视觉编码器捆绑了三个设计选择——上游预训练的视觉先验、专用视觉容量、融合前放置；以往模型在数据、架构、算力上各不相同，无法分离各自作用。作者在统一数据、匹配终身算力的控制框架下从头预训练全部模型：视觉先验并非必需，与语言模型联合从头训练的编码器与预训练编码器相当；关键是专用视觉容量，无编码器的模型即使把主干放大同样参数量仍落后；但容量不必放在融合前，放在主干早期层内同样有效，还能降低首 token 延迟。

**为什么值得读**　设计多模态模型、纠结要不要预训练视觉编码器时必读的控制实验：省掉单独的视觉预训练阶段、把容量放进主干早期层，是可行的。

## 七、效率与部署

### 9. [LazyWeights：边端大模型按需解码权重，省显存又省电](https://arxiv.org/abs/2611.17108)

*LazyWeights: Decode-on-Demand Edge LLMs*

`arXiv:2611.17108` · 2026-11-12

| 指标 | 数值 |
| --- | --- |
| 体积 | 比 llama.cpp 最优格式小 **5.7—31.4%** |
| 延迟 | 最多 **−36%** |
| 能耗 | 最多 **−38%** |

**核心贡献**　GPTQ、AWQ、llama.cpp 的 K/I 量化对矩阵的每个整数码花同样比特，但码值分布远非均匀。LazyWeights 保持这些格式，调整 GPTQ 使编码可压缩，用 Huffman 无损编码交错通道，并在 DRAM 与 L2 之间的小单元按需解码——GPU 内核不用改，DRAM 只搬运编码后的字节。

**为什么值得读**　做边端部署、显存与带宽受限时优先看。数据基于 Phi-3-mini、Mistral-7B、SmolLM-1.7B，在 1% 与 3.5% 困惑度预算下测得。

## 八、评估与安全

### 10. [CapLite：小模型智能体防提示注入，别让模型自己写安全规则](https://arxiv.org/abs/2611.17115)

*CapLite: Prompt-Injection Defense for Small Language Model Agents without Model-Written Security Artifacts*

`arXiv:2611.17115` · 2026-11-12

| 指标 | 数值 |
| --- | --- |
| 攻击成功 | 13,935 个 episode 中 **0** 次 |
| token 开销 | CaMeL 的 **18%** |

**核心贡献**　CaMeL、Progent 等执行型防御让智能体自己的模型写安全产物（程序、权限策略、依赖图），再由代码强制执行；作者在 15 个开源模型（13 个为 1.7B—12B）上发现小模型写不出可信的安全产物：Progent、IPIGuard、DRIFT 的策略在 14/13/11 个模型上可被攻破，CaMeL 的程序在高达 68% 的 episode 里跑不起来。CapLite 改为从工具 schema 派生策略、在读任何工具结果前提交写调用，且只有用户请求中明确写出的接收方、金额、对象、目的地才放行写操作。

**为什么值得读**　给小模型 Agent 做提示注入防御时必读：安全规则别让被保护的模型自己写，从工具 schema 派生、在读工具结果之前就提交。
